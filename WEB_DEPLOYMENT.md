# JobSearcher browser app

The Vite/React browser application is in `web/` on the `github-pages` branch of `Alehaaaa/JobUI`. The public site is published from the separate `Alehaaaa/JobSearcher` repository, whose `github-pages` branch contains the contents of the Vite build directory `web/dist/` at its root. Run `npm --prefix web install`, `npm --prefix web run build`, then `bash scripts/publish_pages.sh` after reviewing and committing changes to update that site.

The website downloads the studio definitions from `https://raw.githubusercontent.com/Alehaaaa/JobUI/refs/heads/main/config/studios.json` on each device, with a bundled configuration as fallback. Jobs are fetched directly by JavaScript running in that device's browser. There is no scheduled crawler or remote application server.

Browser security enforces CORS on each external jobs endpoint. The client attempts requests directly, then falls back to free public `cors.dev` for eligible unauthenticated GET/HEAD requests. This proxy receives the requested public URL and never receives passwords, tokens, cookies or private headers; the anonymous service limits include 1 MiB per response and a 10-second upstream deadline. For Workable's four configured POST feeds, a same-provider public widget GET is available. Pixar's blocked Workday POST can be recovered from Disney's public careers GET; Digital Domain's HTTP-only RSS and WildBrain's TalentSoft jobs can be read through publicly accessible Jina Reader GET endpoints with their real application links. These fallbacks all run on demand in the visitor's browser, and the UI labels proxied jobs.

Providers can change their policies or throttle free public intermediaries. Crafty Apes still requires a cross-origin CSRF cookie for its original search POST, while Kojima Productions needs a POST without a verified equivalent public GET. Neither studio has a verified job-level public fallback. Failed studios display a clear error and their careers-page link, without invented listings.

To run locally, use `npm --prefix web run dev`; to validate deployment, use `npm --prefix web run build` and `npm --prefix web run preview`. File URLs lack consistent fetch support.

For scraper-parity verification against the original `origin/main` Python implementation, run `cd web && npm run audit:live`. It runs every studio individually in separate Python and Node processes with bounded deadlines and writes JSON, CSV and Markdown reports under `web/audit-results/`. The last full 81-studio extraction audit reported 70 exact nonempty matches, 10 both-empty feeds, and one Crafty Apes CSRF error; a separate live test compares every Digital Domain and WildBrain alternate-feed record with original Python using `npm run test:live`. Run `npm test` for fast parsing, proxy, browser-safe fallback, and source-validation tests. Node's HTTP client does not enforce browser CORS, so parity checks validate extraction rules, while real Chrome checks validate browser accessibility. Empty feeds remain unverified.
