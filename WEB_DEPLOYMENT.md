# JobSearcher browser app

The Vite/React browser application is in `web/` on the `github-pages` branch of `Alehaaaa/JobUI`. The public site is published from the separate `Alehaaaa/JobSearcher` repository, whose `github-pages` branch contains the contents of the Vite build directory `web/dist/` at its root. Run `npm --prefix web install`, `npm --prefix web run build`, then `bash scripts/publish_pages.sh` after reviewing and committing changes to update that site.

The website downloads the studio definitions from `https://raw.githubusercontent.com/Alehaaaa/JobUI/refs/heads/main/config/studios.json` on each device, with a bundled configuration as fallback. Jobs are fetched directly by JavaScript running in that device's browser. There is no scheduled crawler or remote application server.

Browser security enforces CORS on each external jobs endpoint. The client attempts requests directly, then falls back to free public `cors.dev` for eligible unauthenticated GET/HEAD requests. This proxy receives the requested public URL and never receives passwords, tokens, cookies or private headers; the anonymous service limits include 1 MiB per response and a 10-second upstream deadline. For Workable's four configured POST feeds, a same-provider public widget GET is available. Pixar's blocked Workday POST can be recovered from Disney's public careers GET; Digital Domain's HTTP-only RSS and WildBrain's TalentSoft jobs can be read through publicly accessible Jina Reader GET endpoints with their real application links. These fallbacks all run on demand in the visitor's browser, and the UI identifies their actual source.

Crafty Apes is supported through a public Jina Reader GET rendition of its official Dayforce job board with 16 individually linked application pages; all 16 current postings were checked against the original Python scraper. The original Dayforce API itself still requires a cross-origin CSRF cookie. Kojima Productions is supported through its officially linked HRMOS careers board using the free cors.dev GET proxy and a Jina Reader backup. All 35 postings found by the original Python scraper correspond to real HRMOS jobs; the HRMOS board has three additional legitimate posts (38 total) and those are retained. On the Jina backup, HRMOS locations are unavailable and deliberately left unspecified.

The app additionally supports an optional community-contributed Google Sheet, enabled by the **Community Sheet** toolbar control. Each device directly requests the public GViz CSV from `https://docs.google.com/spreadsheets/d/1eR2oAXOuflr8CZeGoz3JTrsgNj3KuefbdXJOmNtjEVM/gviz/tq?tqx=out:csv&gid=0` with no user sign-in, API key, or third-party relay. Contributed listings remain labeled separately; their original studio names, public application URLs/email contacts, posting dates, and explicit experience levels are preserved. The sheet is optional because it is curated by third parties independently of the 81 verified studio scraper configurations. The user's browser keeps filter, enabled-studio, auto-refresh and source preferences locally.

Providers can change their policies or throttle free public intermediaries. When both the original endpoint and its verified public fallback fail, the affected studio shows an explicit error and its careers page link. Never treat a failed request as a true empty listing or invent jobs to mask a failure.

To run locally, use `npm --prefix web run dev`; to validate deployment, use `npm --prefix web run build` and `npm --prefix web run preview`. File URLs lack consistent fetch support.

For scraper-parity verification against the original `origin/main` Python implementation, run `cd web && npm run audit:live`. It runs each studio in separate Python and JavaScript processes with bounded deadlines and writes JSON, CSV and Markdown reports under `web/audit-results/`. Run `npm run test:live` for current Python parity of Crafty Apes, Kojima's official application-link overlap, Digital Domain, WildBrain and the anonymous community Sheet, or `npm test` for fast deterministic parsing and recovery checks. Node's HTTP client does not enforce browser CORS, so use a real Chrome test of the Vite production build to establish client fetch accessibility. Empty feeds remain unverified until checked against their official sources.
